# Memory: Preferences

## How I Like Things Done

### Communication Style
- **Be concise** - direct answers without lengthy explanations
- **Challenge me** - correct wrong terms, phrases, definitions immediately
- **Teach, don't just solve** - especially for TypeScript, explain the "why"

### Code & Documentation
- **Modular over monolithic** - split big files into focused small files
- **No fluff** - keep documentation lean and actionable
- **Update docs as we go** - don't wait until end of session
- **Show code location** - file:line numbers when referencing code

### Learning Materials
- **One concept per file** - easier to study later
- **Include examples** - real code, not abstract descriptions
- **Quick reference tables** - for lookups (API endpoints, statuses, etc.)

### When I'm Stuck
1. Explain the concept/problem first
2. Give hints, not full answers
3. Let me try and fail
4. Review and guide to discovery

### Working Style
- **Auto-document discoveries** - when we learn something new, add to learning materials
- **Use TODO lists** - file-based, not in-memory tasks
- **Focus on understanding** - not just making it work
